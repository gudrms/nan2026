# ADR-001: 프로젝트 방향 결정

- **날짜**: 2026-07-24
- **상태**: 승인됨 (Accepted)
- **참여**: 지형근 (1인 개인 참여) *(→ ADR-002에서 2인 팀으로 변경)*

---

## 1. 배경 (Context)

NHN 게임 AI 트랙 사전 과제 제출을 위한 프로젝트 방향 결정이 필요하다.

### 과제 제출물 (5개, 하나라도 누락 시 심사 제외)

| # | 제출물 | 형태 |
|---|---|---|
| 1 | 플레이 가능한 빌드 + 전체 소스 | 웹(GitHub Pages) 또는 모바일(APK/테스트 링크). **PC exe 금지**. 커밋 기록 유지 필수 |
| 2 | 플레이 동영상 | 30~60초, YouTube. AI 조작·합성 불가, 실제 플레이 화면 |
| 3 | 게임 소개·설명 문서 | PDF (개요, 플레이 방법, 실행 방법, 링크) |
| 4 | AI 활용 기술 문서 | PDF (AI 도구·프롬프트·활용 내역, 외부 에셋/오픈소스 출처) |
| 5 | 팀원 롤 기술서 | ~~1인 참여이므로 생략~~ *(→ ADR-002: 2인 확정으로 **제출 필요**)* |

- 심사 계정: `dl_gameai_reviewer@nhn.com`

### 과제 의도 분석

- 심사 계정명이 `gameai_reviewer`이고 **AI 활용 기술 문서가 별도 제출물**로 요구됨
  → 이 과제의 본질은 "완성도 높은 게임"이 아니라 **"AI를 도구로 활용해 만들어내는 역량"** 검증
- 30~60초 영상 기준 → 대작이 아닌 **작지만 완성되어 즉시 실행되는 게임** 기대
- 커밋 기록 유지 + 출처 명시 의무 → **과정의 투명성**이 통과 조건. 도용 시 선발 취소

### 보유 자산: DiceForest (주사위의 숲)

- Unity 2022.3.42f1 모바일 보드게임. C# 90개 파일 / 약 8,000줄
- 서버·네트워크 의존성 없음 (로컬 AI 봇 대전)
- 팀 프로젝트 산출물로 보이며(타인 명의 문서 포함), 커밋 기록이 "최초 업로드" 1개뿐

---

## 2. 결정 (Decisions)

### D1. 기존 DiceForest 제출이 아닌 **신규 제작**

- 기존 프로젝트는 "AI와 함께 개발한 과정"(커밋 기록·프롬프트)이 없어 과제 핵심 평가 축을 충족 불가
- 팀 산출물을 그대로 제출하면 저작권/도용 리스크 → 선발 취소 사유
- DiceForest는 **컨셉·구조 아이디어 참고만** 하고 코드·에셋은 전부 새로 제작
- AI 활용 문서에 "기획 영감은 과거 유사 프로젝트에서, 구현은 전부 신규"임을 투명하게 명시

### D2. Unity가 아닌 **웹 기반 (HTML/CSS/JS + Canvas)**

| 근거 | 설명 |
|---|---|
| 제출 요건 | 웹 또는 모바일 중 하나면 충분. 웹이 심사자 접근성 최고 (링크 클릭 → 즉시 플레이) |
| 배포 | GitHub Pages에 push 한 번으로 배포. Unity WebGL은 용량·로딩·MIME 문제 리스크 |
| AI 페어코딩 궁합 | 텍스트 기반 코드라 AI와의 반복 작업·커밋 기록 축적에 유리. Unity 씬/프리팹은 바이너리·YAML이라 불리 |
| 트레이드오프 | 3D 물리 연출은 포기 → 2D 애니메이션으로 대체 (30~60초 데모엔 충분) |

### D3. 게임: **윷놀이 2v2** (플레이어 + 아군 AI 1 vs 적 AI 2)

주사위 레이스류 대비 선택 이유:

- **차별성**: 한국 전통 게임 + AI 조합. 한국 기업 심사에서 규칙 설명 불필요, 즉시 공감
- **재미 내장**: 잡기(캡처)/업기/역전이라는 검증된 재미가 룰 차원에 존재 — 데모 영상의 극적 장면(적 AI가 말을 잡으며 도발 → 아군 AI 반응)이 자연스럽게 발생
- **AI 서사 풍부**: AI 페르소나 3개(아군 1, 적 2)의 상호작용 → AI 활용 문서 소재 풍부
- **구현 경량**: 3D 주사위 물리 불필요. 도개걸윷모 확률표 + 클릭 던지기로 충분
- **도용 시비 원천 차단**: DiceForest와 완전히 다른 게임

### D4. AI 아키텍처: **판단 AI / 성격 AI 2-레이어 분리**

| 레이어 | 역할 | 구현 |
|---|---|---|
| **판단 AI** | 어떤 말을 움직일지·잡을지·업을지 결정 | 룰 기반/휴리스틱 (로컬, 빠르고 안정적) |
| **성격 AI** | 결정·상황에 맞는 캐릭터 대사 생성 → 음성 출력 | LLM(GPT API) + TTS |

- 게임 진행은 API 지연·실패와 무관하게 항상 동작 (LLM 실패 시 프리셋 대사 폴백)
- "게임 로직 AI와 생성형 AI를 목적에 맞게 분리 설계"라는 기술 서사 확보
- 봇의 이동 판단 자체를 LLM에 맡기는 방식은 **기각**: 지연으로 템포 붕괴, 실패 시 게임 정지, 단순 결정에 LLM은 과잉

### D5. 음성: **TTS 채택, STT는 후순위**

- **TTS (채택)**: LLM 생성 대사를 캐릭터별 다른 보이스로 재생. 데모 임팩트 큼. GPT 프록시 서버에 엔드포인트 추가만으로 구현
- **STT (보류)**: 클릭 한 번인 조작을 음성으로 대체할 게임플레이 필연성 약함. 시간 여유 시 브라우저 내장 Web Speech API(무료)로 보너스 기능만 고려

### D6. API 키 보호: **서버리스 프록시 필수**

- GitHub Pages는 정적 호스팅 → 클라이언트에 API 키 포함 시 공개 저장소에서 즉시 노출
- Cloudflare Workers 또는 Vercel Functions(무료 티어)로 프록시 구성, 키는 서버 측에만 보관
- 브라우저 → 프록시 → OpenAI API 구조

---

## 3. 스코프 가이드 (초기 합의)

- **말판**: 기본 순환 경로만 우선 구현. 지름길(사잇길)·빽도는 후순위
- **핵심 룰**: 이동 + 잡기 + 업기 + 완주. 잡으면 한 번 더 등 기본 룰 포함
- **대사 트리거**: 매 턴이 아닌 **이벤트 순간만** (잡기/업기/완주/역전 등) — API 비용 절약 + 게임 템포 유지
- **보이스**: 아군/적1/적2 각각 다른 TTS 보이스 프리셋 배정

## 4. 결과 (Consequences)

- 신규 저장소에서 AI 페어코딩 커밋 기록이 자연스럽게 축적 → 제출물 1·4 요건 동시 충족
- 서버리스 프록시라는 최소 인프라 1개 추가 (무료 티어로 비용 0원 목표)
- 3D 연출 포기 대신 개발 속도·배포 안정성 확보
- 윷놀이 전체 룰 미구현 상태로 시작 — 지름길 등은 코어 루프 완성 후 판단

## 5. 다음 단계

1. 말판 경로·턴 순서·캡처 룰 상세 정의
2. 기술 스택 확정 (프레임워크, 렌더링 방식, 프록시 구조)
3. 신규 GitHub 저장소 생성 및 개발 시작

# ADR-002: 팀 구성 확정 (1인 → 2인)

- **날짜**: 2026-07-25
- **상태**: 승인됨 (Accepted)
- **참여**: 지형근(개발), 황인섭(기획)

## 1. 배경 (Context)

ADR-001은 "1인 개인 참여"를 전제로 제출물 5(팀원 롤 기술서)를 생략하기로 했다.
그러나 CONCEPT.md 작성 시점부터 황인섭(기획)이 합류하여 문서 간 구성원 표기가 불일치했다
(CONCEPT: 2인 / ADR-001: 1인). 제출물 구성과 직결되므로 확정이 필요하다.

## 2. 결정 (Decision)

**2인 팀으로 확정한다.**

| 이름 | 역할 | 담당 영역 |
|---|---|---|
| 지형근 | 개발 | 설계·구현·테스트·배포, AI 페어코딩 주도 |
| 황인섭 | 기획 | 게임 컨셉·캐릭터·세계관, 룰/밸런스 방향, 대사 톤 검수 |

- ADR-001의 "제출물 5 생략" 결정을 **폐기**한다.

## 3. 결과 (Consequences)

- 제출물이 4종 → **5종** (팀원 롤 기술서 PDF 추가). Requirements 기준 "2인 이상 팀" 제출 대상
- 팀원 롤 기술서에 역할·담당 구현 영역·협업 방식을 기재해야 하므로, 분업 내역을 개발 중 기록해 둔다

# ADR-003: 캐릭터 비주얼 SVG → 팀 자체 제작 이미지, 이름·게임명 확정

- **날짜**: 2026-07-30
- **상태**: 승인됨 (Accepted)
- **참여**: 지형근(개발), 황인섭(기획)

## 1. 배경 (Context)

ADR-001·CONCEPT §8은 라이선스 리스크 차단을 위해 "외부 이미지 에셋 0개, 전량 SVG/CSS 코드 생성"을 원칙으로 삼았다.
이후 기획이 캐릭터 이미지(4인 idle PNG + talk GIF + 단체 일러스트)를 직접 제작·전달했고,
캐릭터 이름과 게임명도 확정안이 나왔다.

## 2. 결정 (Decisions)

### D1. 캐릭터 비주얼을 기획 제작 이미지로 교체

- **팀 자체 제작물은 "외부 에셋"이 아니다** — 원칙의 목적(타인 저작물 라이선스 리스크 차단)에 저촉되지 않음
- idle PNG(기본) + talk GIF(발화 중) 2상태로 표시하고, **emotion 4종 연동은 CSS 오버레이로 유지**
  (LLM emotion → 표정 구동은 인게임 AI 연출의 핵심이므로 포기하지 않는다)
- emotion별 이미지 4종×4인은 기획이 동일 도구로 추가 생성 예정 — 도착 시 오버레이를 이미지로 교체
- 제작 도구·방식은 AI_USAGE 출처 표에 기재 (제출 요건 — AI 생성이면 도구명 필수)
- 캐릭터 외 요소(윷판·말·이펙트)는 기존 SVG/CSS 유지

### D2. 이름·게임명 확정

| 항목 | 기존 (가제) | 확정 |
|---|---|---|
| 게임명 | 윷놀이: 까치호랑이 한판 | **윷놀이 : 까치호랑이** |
| 까치 (아군 AI) | 깍이 | **까비** |
| 호랑이 (적 리더) | 범발톱 | **범이** |
| 여우 (적 참모) | 꼬리아홉 | **여울** |
| 플레이어 | (호칭 없음, "대장") | **도령** (까비는 계속 "대장"이라 부름) |

- 코드 내부 actor ID(`kkaki`/`beomtiger`/`ninetail`/`player`)는 유지 — 표시명·프롬프트만 변경

## 3. 결과 (Consequences)

- AGENTS.md 절대 규칙 3, CONCEPT §8, README의 "이미지 에셋 0개" 문구를 "팀 자체 제작 이미지 + 그 외 전량 코드 생성"으로 갱신
- 이미지 총 ~7MB — 모바일 로딩을 위해 최적화(WebP 변환 등) 검토 항목 추가
- 페르소나 프롬프트·프리셋 대사·UI 표시명 일괄 변경 (호칭 변경으로 TTS 세션 캐시는 자연 무효화)
