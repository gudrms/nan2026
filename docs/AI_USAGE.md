## 세션 로그

### S1. 2026-07-24 — 과제 분석·컨셉·설계 (Claude Code)

> 결정의 상세 근거는 [ADR.md](./ADR.md)·[spec.md](./spec.md)에 있다. 여기는 **AI를 어떻게 활용했는지의 과정**만 기록한다.

**AI에게 시킨 일과 진행 방식**
- 과제 공고문 원문을 주고 **출제 의도 분석** 의뢰 → "결과물이 아닌 AI 활용 개발 과정 평가"라는 해석 확보. 기존 Unity 프로젝트(DiceForest)의 제출 리스크(커밋 기록 부재, 팀 산출물 저작권)를 AI가 저장소 스캔으로 진단 → 신규 제작 결정의 근거가 됨 (→ ADR-001)
- 플랫폼·언어·프레임워크를 **AI와 문답으로 좁혀감**: Unity vs 웹 / Node vs Python / Next.js 여부 / React 여부. 각 선택지의 트레이드오프를 AI가 제시하고 개발자가 결정 (→ ADR, spec §1)
- 게임 컨셉 2안(주사위 레이스 vs 윷놀이)을 AI에 비교 평가시킴 → 윷놀이 2v2 채택, 까치호랑이 민화 모티프의 캐릭터·세계관을 AI와 공동 설계 (→ CONCEPT.md)
- 기존 저장소 에셋의 **라이선스를 AI가 전수 조사** (license.txt 확인 포함) → CC0 1건 외 전부 출처 불명 판정 → 외부 에셋 0개 방침 확정

**AI 제안을 기각한 사례** (검증 역량의 증거)
- "봇 이동 판단을 LLM으로" 안 → 기각: 지연·실패가 게임 진행을 블로킹. 판단은 로컬 알고리즘, LLM은 대사 생성만 (2-레이어 분리)
- MCTS/강화학습 제안 → 기각: 사전 과제 스코프 과잉, 마감 리스크

**개발자가 AI 제안을 검증·교정한 사례**
- 개발자: "윷은 1/5 균등 확률이면 되지 않나?" → AI가 이항분포 모델로 반증 (균등 시 추가 턴 40%로 템포 붕괴) → 검증 후 이항분포 채택 (spec §4.3)
- 개발자: "스택이 너무 무난하지 않나?" → AI가 "라이브러리 추가는 역효과, 알고리즘 깊이로 승부" 제안 → 기대값 탐색·시뮬레이션 하네스·대화 메모리·Structured Output 4종 채택 (spec §4)

**산출물**: ADR.md, CONCEPT.md, spec.md, 본 문서

### S3. 2026-07-25 — 게임 코어 구현 M0~M1 (Claude Code)

**AI에게 시킨 일과 진행 방식**
- 스캐폴딩(Vite+React+TS+Vitest)과 게임 코어 7모듈(board/throwYut/state/rules/events/botAI/simulate) + 테스트 44개를 AI 페어코딩으로 구현. "트레이드오프는 보류 목록에 쌓고 기본값으로 계속 진행" 방식으로 개발자 개입 없이 연속 진행 → 보류 결정 7건을 checklist에 목록화(D-1~D-7)해 나중에 일괄 확정
- 방(22) 경유 지름길 분기(5쪽 대각선에서 정지 시 최단 출구 전환), 업기 그룹 이동, 잡기 추가 턴 등 엣지케이스를 테스트 먼저 작성해 고정
- 시뮬레이션 하네스로 실측: 1000판 232ms, 승률 blue 50.7 : orange 49.3(선공 이점 미미), 던지기 분포가 이항분포 이론치와 일치(do 15.4/gae 34.7/geol 34.2/yut 13.1/mo 2.6%), 말 개수별 게임 길이(4개 53회 / 3개 39회 / 2개 26회 던지기) — 밸런싱 결정의 근거 데이터

**테스트가 잡아낸 사례**
- `dangerAt`(피격 위험 확률) 테스트 실패 → 원인은 구현 버그가 아니라 테스트 설계(대기 말의 투입 사정권 합산 누락). 위험도 모델이 "대기 말도 1~5칸을 위협한다"를 반영하고 있음을 역으로 확인

**설계 판단 (AI 제안 채택)**
- @types/node 전역 추가 대신 simulate.ts 내 최소 `declare const process` 선언 — 브라우저 번들 코드에 Node 전역 타입 누출 방지
- 게임 진행 순서(디자인 시안 → 코어)를 뒤집어 코어 우선: M0·M1은 디자인 무의존, 디자인은 기획자가 별도 진행

**봇 개선 정량 검증 (v1 휴리스틱 → v2 기대값 탐색)**
- v2: 수 적용 후 (내 진행 이득 + 상대 손실 + 추가 턴 기대 전진량) − (상대 던지기 확률분포를 펼친 최선 반격 잡기의 기대 손실). 캐릭터 성향 가중치(범발톱 공격형 / 꼬리아홉 안전형 / 깍이 균형) 내장
- 매치업 검증: v2 vs v1 — **선공 시 54.8%, 후공 시에도 54.3%** (각 2000판). 선공 이점(v1끼리 +0.7%p)을 뒤집는 우위로 개선 입증

**산출물**: src/game/ 7모듈, tests/ 5파일(47 테스트), 시뮬레이션 통계

**설계 판단**

### S6. 2026-07-25 — 실배포 프롬프트 검증·훈수(HINT)·M4 연출 (Claude Code)

**실배포 API로 페르소나 프롬프트 검증 (제출물 4 핵심 소재 — 과금 절약 위해 3회만 호출)**
- 대표 케이스 3건(범발톱 도발 / 깍이 반격 티키타카 / 꼬리아홉 견제)을 배포 프록시에 호출 → 말투 캐릭터성은 확보됐으나 **문제 3건 발견**:
  ① 깍이가 시제 오해("이미 잡힌" 상황에 "잡히면 안 돼요") ② 꼬리아홉이 판세 숫자를 그대로 읊음("15와 12라니") ③ 40자 길이 제한 무시
- → 프롬프트 보강: "상황은 이미 일어난 일" 명시, 진행도 숫자 낭독 금지, emotion-감정 일치 규칙, 길이 규칙 완화·명료화(최대 두 문장 40자)

**깍이 훈수(HINT) 구현 — 판단 AI × 성격 AI 결합 지점**
- 플레이어 5초 장고 + 선택지 2개 이상일 때, 기대값 탐색이 계산한 최선 수의 유형(잡기/완주/업기/지름길/전진)을 상황 요약에 담아 깍이 대사로 생성 (폴백 프리셋 5종 병행). 브라우저 실동작 확인

**M4 연출**
- 효과음 전량 Web Audio 합성(외부 오디오 에셋 0개 유지): 윷 던지기(대역필터 노이즈 나무 클릭 4연타), 잡기(하강 임팩트), 완주(아르페지오) 등 6종. 음소거 토글 연동
- 캐릭터 SVG 반응형 전환 → 모바일 375px 가로 오버플로 없음 확인

**기획 실플레이 피드백 반영** (배포판 플레이 후 3건)
- "이벤트·음성과 말풍선 싱크가 안 맞는다" → 말풍선 수명을 고정 3.6초에서 **해당 대사의 TTS 재생 종료 시점 동기화**로 재설계 (speak()가 재생 종료에 resolve하는 구조로 ttsClient 개편)
- "화면이 펼쳐져 잘 안 보인다" → 윷 결과를 판 위 오버레이로 이동, 폭·간격 축소
- "말 이동 시 팀 색이 안 보인다" → 말 확대 + 팀색 후광 + 이동 그림자

**산출물**: 프롬프트 v2(api/dialogue.ts), HINT 파이프라인, src/audio/sfx.ts, 말풍선-음성 싱크, 모바일 보정

### S7. 2026-07-25 — 연출 개선 2차: 기획 실플레이 피드백 8건 (Claude Code)

**진행 방식** — 기획이 배포판을 플레이하고 피드백 8건 전달 → AI가 항목별 타당성·비용 평가표를 만들어 우선순위 합의 → 4개 작업단위로 나눠 구현·검증·커밋 (전 과정 로컬 폴백 모드로 API 과금 0)
- F-3·4: 좌우 팀 배치 (CONCEPT §7.2 원안 복원) / F-5·6: 가락 토스 연출·봇 템포·턴 바운스 / F-7·8: 등급별 결과음·경로 스텝 이동(코어의 move.path 설계가 그대로 활용됨) / F-1·2: 훈수 추천 칸 배지·플레이어 표정·음성 동기 타자기 말풍선

**AI가 검증 중 발견·해결한 문제 2건**
- 로컬 vite dev의 /api 404 응답이 타임아웃까지 매달려 폴백이 3초 지연 → dev는 프리셋 폴백 모드로 즉시 동작하게 분기 (spec §5의 "Vite dev + 프리셋 폴백 모드" 명문화)

### S9. 2026-07-25 — 동기식 턴 진행 재설계 (Claude Code)

- 기획 피드백 "Web Speech 사회자 품질 미달·반복, 비동기라 부자연" → **사회자 폐기, 캐릭터 본인이 턴을 이끄는 동기식 턴 드라이버**로 재설계: 차례 알림("이 몸의 차례다!") → 던지기 → 결과 리액션("모다!! 크하하!") → 이동이 각 음성 종료를 기다리며 순차 진행. 플레이어 턴은 깍이가 안내·리액션 대행

### S10. 2026-07-25 — 연출 5차: 대사량·BGM·잡기 임팩트 (Claude Code)

### S11. 2026-07-30 — 음성 템포·README·중간 평가 리뷰 (Claude Code)

**AI가 개발자 지시를 교정한 사례**

**README 작성 — 개발자가 AI 산출물을 교정한 사례**

**AI를 요구사항 기반 평가관으로 세워 중간 코드리뷰·채점**
